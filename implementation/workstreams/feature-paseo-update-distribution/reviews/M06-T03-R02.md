## Blocking finding

The R01 correction adds `wait_for_stock_update(...)`, which can poll across predecessor -> missing-container -> candidate states and can be called again after an interruption. It still does not implement or prove the crash-safe gesture-to-observer binding required by the Card and PUD-REQ-025.

There is no durable launcher, supervisor, Unraid hook/action, or other mechanism in the reviewed implementation that guarantees this observer is already running when the operator invokes stock DockerMan Update, or that restarts it after an observer/process crash. The restart test explicitly invokes `wait_for_stock_update(...)` a second time from the test itself. That proves the function is restartable from the durable guard; it does not prove that the stock DockerMan gesture is crash-safely bound to automatic observer invocation/restart.

Therefore the same failure mode identified by R01 remains possible: stock Update may complete while no observer is alive, leaving the exact guard armed and never entering the bounded immediate-acceptance transaction. A restartable polling primitive is necessary but not sufficient for the required stock-button binding.

The reviewed change from `predecessor_digest` to the actual guard field `previous_digest` is correct, and the polling logic preserves authoritative Docker inspect, rejects a third digest, and does not trust DockerMan cache/status. Those properties do not close the missing lifecycle binding.

The correction must exercise interruption at the process/lifecycle boundary rather than proving only that a caller can invoke the polling function again. Preserve authoritative Docker inspect, fail-closed ambiguity handling, bounded immediate acceptance/rollback, and the requirement that production `:accepted` and the active production container remain unchanged during this Card.
