## Blocking finding

The production `:accepted` writer does not perform validated transaction-guard readback. Its CLI loads `--guard` with the generic `load_json()`, and `validate_production_gate()` trusts the supplied `state`, candidate/predecessor/config/rollback digests and `binding_digest` without recomputing the binding from those fields or verifying that the rollback anchor remains independently retrievable.

Therefore a stale or manually constructed JSON object can satisfy the writer gate when its arbitrary `binding_digest` matches the final-gate record. This bypasses the Card acceptance requirement that production accepted-channel writing fail closed unless transaction-guard inspect/readback proves the exact binding is already armed.

The dedicated `paseo_transaction_guard.load()` path does recompute the binding, validates rollback identity and verifies the rollback anchor, but the production promotion CLI does not use it.

## Required correction

Make the production writer consume validated guard readback (or equivalently perform the same strict validation itself) before allowing `:accepted` promotion. Add a regression test proving a forged/stale guard JSON with superficially matching fields/binding evidence is rejected before registry inspection or mutation. Preserve the non-production writer behavior and all existing M06-T01 boundaries.
