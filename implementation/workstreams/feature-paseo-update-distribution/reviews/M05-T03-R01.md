## Blocking finding

The Card explicitly requires malformed/stale identity rejection and a durable ledger containing exactly three distinct production-known-good generations.

In `scripts/paseo_known_good.py`, `rotate(ledger, new)` validates only digest syntax and treats only `new == ledger["current"]` as idempotent. It does not reject a stale identity equal to `previous_1` or `previous_2`.

For a valid ledger `{current:A, previous_1:B, previous_2:C}`, rotating to stale `B` returns `{current:B, previous_1:A, previous_2:B}`, which contains a duplicate identity and violates the same module's strict ledger invariant. The returned rotated ledger is not revalidated before return/write.

The focused test named `test_rejects_malformed_stale_or_duplicate_identity` exercises malformed, duplicate-at-load, and extra-slot inputs, but does not exercise stale rotation to `previous_1` or `previous_2`. Therefore the claimed stale-identity rejection evidence is incomplete and the implementation can durably write an invalid ledger.

## Required correction

Reject stale rotation targets already present in `previous_1` or `previous_2` (or otherwise guarantee rotation cannot emit a ledger violating strict load invariants), and add focused regression coverage for both stale predecessor slots and durable write/readback behavior.
