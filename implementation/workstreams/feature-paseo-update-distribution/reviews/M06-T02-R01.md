## Blocking finding

The GREEN path does not enforce the Card-required local core-probe set. `run_transaction` accepts an arbitrary probe list and commits whenever that supplied list has no failures. Therefore a freshly armed guard can be driven through `armed -> observed -> validating -> committed` with `probes=[]`, without proving exact running digest, container health, Paseo/Pi RPC/provider path, mounts/ownership, or required core invariants.

The current tests verify callbacks carrying those names when supplied, but do not prove that omission of any required core probe fails closed. This violates the Card acceptance requirement that **all required local core probes must pass before GREEN commit** and weakens PUD-REQ-027/ADR-PUD-003 immediate-acceptance safety.

## Required correction

Make the immediate-acceptance transaction fail closed unless the complete required local core-probe set is present exactly once (or otherwise structurally guaranteed by the transaction API), and add regression coverage proving empty/missing/duplicate required probes cannot reach committed. Preserve the existing transient-remote-outage policy and exact-predecessor rollback behavior.
