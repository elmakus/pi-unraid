- New `pi-unraid-service` is the normal non-root PID1 after the existing bounded root entrypoint initialization.
- Service startup clears ephemeral stale service markers, performs the T01 runtime reconciliation, and publishes an ephemeral ready marker only after current-start reconciliation plus runtime health succeeds. Persistent prior success alone cannot make the current Compose startup healthy.
- Planned SIGTERM closes managed-launch admission under the same `flock`, revalidates each registration against `/proc`, current UID and start-time before signaling, sends SIGTERM first, waits the complete configured internal grace, and sends SIGKILL only to still-valid surviving registrations.
- The grace deadline uses millisecond resolution so the configured duration is not shortened by whole-second boundary rounding.
- `compose.yaml` keeps the existing bounded `json-file` rotation, adds the service healthcheck, keeps the default internal grace at 12 s, and sets Compose outer `stop_grace_period: 20s`.
- Dockerfile default CMD now starts `pi-unraid-service`; explicit commands used by disposable tests remain supported through the existing entrypoint.
