## RED correction

### R1 — native persisted-session/resumability proof

The lifecycle verifier no longer hashes an arbitrary file while running real Pi with `--no-session`.

It now:

1. creates an empty session path beneath the disposable persistent Pi home;
2. opens that exact path through packaged Pi `--mode rpc --offline --session`, causing Pi's native SessionManager to materialize a valid JSONL session header;
3. records the native `sessionId` returned by `get_state` and validates it against the persisted session header;
4. launches the real TTY-backed packaged Pi through the supported `pi` launcher using that same native session path;
5. waits for the native JSONL to stabilize, hashes the actual `.jsonl` immediately before planned service stop, then performs stop + container removal/recreation;
6. verifies the native session hash is unchanged across that stop/recreation; and
7. reopens the same file through packaged Pi RPC after recreation and requires the same `sessionFile` and `sessionId`.

No provider request, OAuth credential or live user session is needed for this native readability/resume proof.

### R2 — outer grace must exceed production inner grace

Production `compose.yaml` no longer publishes `PI_UNRAID_MANAGED_GRACE_SECONDS` from ambient/operator Compose interpolation. The production service therefore keeps its accepted internal default of 12 seconds while Compose remains fixed at 20 seconds.

The disposable lifecycle fixture still supplies an explicit shorter grace override for bounded test execution. The verifier renders base production Compose while an ambient `PI_UNRAID_MANAGED_GRACE_SECONDS=30` is present and fails if that variable leaks into the rendered production service environment.
