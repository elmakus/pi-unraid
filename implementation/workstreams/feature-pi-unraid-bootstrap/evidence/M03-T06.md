## Recovery-domain finalization

Phase 1 recovery is intentionally separated into four domains:

1. **Pi runtime candidate failure** — use the accepted M02 LKG/seed path; production behavior was exercised non-disruptively in M03-T05.
2. **Pi deployment image/config/startup failure** — use retained deployment rollback; M03-T05 proved actual retained-image rollback without durable-data rollback.
3. **Codex-LB/model-access dependency failure** — Pi durable runtime/session/filesystem state remains independent; diagnose/recover Codex-LB under its own authority and never substitute direct Pi OAuth.
4. **Persistent-data damage** — stop writes and use the user's existing backup/restore authority; binary/runtime rollback is not a data-restore mechanism.

No recovery path is authorized to restore Pi home/projects/worktrees or Codex-LB account state backward merely to make an older binary run.
