- Milestone: `M02`

## Authority slice

- Master Plan / milestone contract: `planning/MASTER_PLAN.md#M02 — Recoverable runtime and deployment lifecycle`, especially M02-W1
- Requirements: `requirements/PI_UNRAID_BOOTSTRAP.md` PIB-REQ-014/017 plus applicable global/data-integrity invariants
- Accepted decisions: `decisions/PIB_ADR_002_RUNTIME_LAYOUT.md`, `decisions/PIB_ADR_003_UPDATE_ROLLBACK.md`
- Relevant OpenSpec: `openspec/changes/m02-runtime-lifecycle/`

- Accepted dependency results: terminal GREEN M01; `implementation/workstreams/feature-pi-unraid-bootstrap/evidence/M01-acceptance.md`

### Must preserve

- latest **stable** only; no beta/nightly/prerelease activation;
- image seed remains immutable/offline-capable and is never overwritten by downloaded runtime state;
- downloaded runtimes and lifecycle metadata live under persistent `/home/pi`, not in `~/.pi/agent` auth/session/config payload;
- a candidate is not promoted until exact-version and real Pi RPC `get_state` readiness checks pass;
- install/probe failure preserves prior LKG/selection; registry/offline failure degrades without falsely blacklisting a version;
- mutation is serialized/atomic and safe across interruption/overlap;
- known failed candidate cannot be immediately reselected in a restart loop;
- selected runtime must be compatible with the current image/Node; image seed remains final local fallback;
- no stale successful readiness state when no runtime is usable;
- M01 mount/security/non-root invariants remain intact.

### Must not / rationale that must travel

- Do not perform live OAuth/provider requests.
- Do not add Docker socket or new live container mounts.
- Do not treat `--version` alone as startup proof.
- Do not make mock-only tests substitute for a real packaged-Pi staging/readiness path.

## Dependencies

- M01 terminal GREEN integrated acceptance.

## Outcome

A repository-owned runtime manager can reconcile the latest stable Pi into isolated persistent slots, atomically select a proven working runtime, fall back to LKG/image seed on bounded failures and publish honest non-secret readiness state.

## Scope

### Included

- Dockerfile changes needed to preserve the M01 Pi seed separately from the user-facing launcher and add explicit locking support;
- `pi-unraid-runtime` reconciliation/status/health/retry behavior;
- persistent runtime slot/state layout from OpenSpec;
- user-facing `pi` runtime-selection launcher, excluding managed PID registration owned by T02;
- deterministic and real-package runtime-selector verification.

### Excluded

- service PID1 supervision and process shutdown propagation (T02);
- host image/deployment update/rollback (T03);
- production/live OAuth, GitHub or cutover tests (M03).

## Acceptance

- current upstream stable metadata resolves to an accepted stable version compatible with the image Node;
- a real package can be staged as the service user, exact version read back, RPC `get_state` readiness proven and atomically selected;
- selected persistent runtime survives container removal/recreation with unchanged fixture home;
- failed install/probe leaves prior LKG usable after recreation and records non-stale diagnostics;
- immediate retry of a known failed version follows the bounded failed-candidate policy, while explicit retry exists;
- offline/unreachable registry startup uses compatible LKG or image seed;
- interrupted/overlapping reconciliation cannot expose partial slot/state;
- incompatible/broken persistent selection can fall back to image seed;
- status/health fails when all candidates are deliberately unavailable;
- M01 base/Compose regressions remain GREEN.

## Required tests / checks

- real `npm view` + real staged `@earendil-works/pi-coding-agent` install with `engine-strict` and `--ignore-scripts`;
- real exact candidate `--version` and RPC `get_state` probe;
- deterministic prerelease, offline, install-failure, startup-failure, cooldown and unavailable fixtures;
- two overlapping reconcile attempts;
- remove/recreate container using the same fixture home;
- `scripts/verify-base-image.sh` and `scripts/verify-compose-foundation.sh` regressions.

## External write/readback needs

Disposable Tower Docker containers plus unique `/tmp` fixture home only. No live `/mnt/user/appdata/pi-unraid/home`, project/worktree or credential mutation.

## Independent review

`REQUIRED` — persistent runtime promotion/fallback state controls availability and future production startup behavior; exact failure semantics warrant a fresh independent review.
