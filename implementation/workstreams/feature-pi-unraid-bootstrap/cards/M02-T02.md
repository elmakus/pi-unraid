- Milestone: `M02`

- Dependency: terminal GREEN M02-T01 runtime selector/LKG result

### Must preserve

- normal service PID1 becomes non-root after the existing bounded root initialization;
- supported native `pi` TUI path remains direct and cwd-selectable under `/projects` or `/worktrees`;
- planned Docker/Compose SIGTERM must be propagated to valid managed Pi exec processes before forced termination;
- registry entries must resist PID reuse and stale-file signaling;
- default internal Pi grace is 12 s and outer Compose grace is 20 s; fixtures may override shorter values;
- current Pi SIGTERM path is the claim boundary; dead-PTY/EIO is not claimed graceful;
- persisted native state remains untouched; no claim that unpersisted in-flight work survives;
- health/readiness cannot report stale success;
- existing 10 MiB x3 Docker log rotation remains bounded.

## Dependencies

- M02-T01 terminal GREEN.

## Outcome

The normal service supervises managed exec-launched Pi instances, exposes honest health, gives current packaged Pi a bounded graceful SIGTERM window, and escalates only non-cooperative managed processes before Docker's outer kill bound.

## Scope

### Included

- managed launcher PID/start-time registration and stale pruning;
- non-root `pi-unraid-service` PID1 supervisor;
- Compose `stop_grace_period` and healthcheck;
- concise lifecycle diagnostics;
- packaged-Pi TUI/session fixture plus non-cooperative escalation fixture.

### Excluded

- changing runtime promotion semantics from T01;
- host image/deployment update/rollback (T03);
- live OAuth/provider/session proof and real host restart (M03).

## Acceptance

- normal service PID1 identity is the configured non-root UID/GID;
- at least one real packaged interactive Pi launched through supported exec/TUI path registers and receives planned SIGTERM;
- the real Pi process exits during the graceful window without supervisor SIGKILL;
- two concurrent managed Pi registrations are independently validated/signaled;
- stale/reused PID metadata is not signaled;
- a registered non-cooperative fixture receives SIGKILL only after the configured internal grace and the whole service stops within the outer bound;
- synthetic/native session state already persisted in fixture home remains readable after stop/recreation;
- runtime unavailability makes Compose health fail rather than retaining stale healthy state;
- M01/T01 regressions remain GREEN.

## Required tests / checks

- real TTY-backed packaged Pi process in disposable container;
- planned `docker compose stop`/SIGTERM timing readback;
- ignore-SIGTERM fixture and bounded escalation timing;
- stale PID/start-time negative test;
- concurrent managed Pi test;
- health transition/readback;
- fixture-home before/after state hashes plus native session/readability probe;
- M01 and M02-T01 regressions.

## External write/readback needs

Disposable Tower Docker/Compose project and unique `/tmp` fixture binds only.
