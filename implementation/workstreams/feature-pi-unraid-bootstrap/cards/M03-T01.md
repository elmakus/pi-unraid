### Must preserve

- Production Pi remains the repository-owned Compose deployment with persistent native `/home/pi`, canonical `/projects` and `/worktrees` binds.
- Service runs non-root with target numeric UID/GID `99:100`; no broad recursive ownership takeover of existing project data.
- No Docker socket, host-root, unrelated appdata mount or inbound SSH service may be introduced.
- Existing `chatgpt-ce-workstation` is independent and must not be modified, recreated, stopped or used as a dependency.
- Initial source synchronization must remain on `feat/pi-unraid-bootstrap`, require a clean checkout and advance only by fast-forward.
- Missing canonical Pi appdata/worktree paths may be created only after the explicit live-write authorization gate.
- The first production start uses the accepted Compose contract and bounded logging/restart/health policy; do not improvise an alternate Unraid template or privileged container.
- Persistent appdata must remain inside the existing Appdata Backup source surface; post-deploy readback must verify the new Pi path/container is not excluded/skipped.
- M03-T01 does not authorize ChatGPT credential entry, Git/GitHub write tests, update/rollback exercises or Docker/host restart.

### Must not / rationale that must travel

- Do not use the already-built M01/M02 fixture images as proof of production deployment without rebuilding from the synchronized production checkout.
- Do not use `scripts/update.sh` as the bootstrap path before a healthy production deployment exists; its contract assumes a current healthy Compose deployment/LKG.
- Do not silently create substitute host paths if the canonical paths cannot be created safely.
- Do not treat a running container as accepted unless health/runtime/user/mount/security readback is GREEN.

- Verify the Appdata Backup configuration sees the new Pi appdata surface and is not configured to skip the new Pi container/path.

- Persist sanitized production-deployment evidence.

- Final Phase 1 acceptance/integration.

## Acceptance

1. Pre-write checkout is clean and fast-forward-only synchronization succeeds to the current approved workstream head.
2. Canonical persistent paths exist with intended `99:100` ownership and no unrelated ownership sweep.
3. Rendered production Compose exactly preserves the accepted mount/security/restart/health/logging contract.
4. Production image builds from the synchronized checkout and the `pi` service becomes healthy.
5. Exact deployed source/image, Node and selected Pi runtime identities are recorded; selected Pi is a compatible stable runtime and readiness is not stale.
6. Running service processes as the configured non-root identity and can write its persistent home without changing project-root ownership.
7. Live mount/process inspection proves no Docker socket, host-root/unrelated-appdata bind, published inbound port or SSH daemon.
8. The new Pi appdata path is within the configured backup source and not explicitly skipped.
9. `chatgpt-ce-workstation` remains running/healthy on the same container/image baseline unless an unrelated external change is separately proven.
10. No later M03 live gate is exercised by this Card.
