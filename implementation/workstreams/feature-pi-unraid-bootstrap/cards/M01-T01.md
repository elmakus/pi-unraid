# M01-T01 — Reproducible base image and stable Pi seed

- Milestone: `M01`

> Stable Task Card contract. Mutable state lives only in the selected workstream Task Board.

## Authority slice

- Master Plan / milestone contract: `planning/MASTER_PLAN.md#M01 — Reproducible non-root development environment`, especially M01-W1 and section 3.1.
- Requirements: `PIB-REQ-001, PIB-REQ-008, PIB-REQ-016` plus applicable global invariants from `requirements/PI_UNRAID_BOOTSTRAP.md`.
- Accepted decisions: `PIB-ADR-001`, `PIB-ADR-002`, and the stable-seed compatibility boundary from `PIB-ADR-003`.
- Relevant OpenSpec: none.
- Accepted dependency results: none.

### Must preserve

- Repository-owned image source; Compose remains deployment source of truth even though Compose wiring is completed in T02.
- Current supported Pi runtime baseline: Node >=22.19; use a current Pi-supported Node 24 Debian base unless current evidence requires an equivalent supported choice.
- Image includes Python, Git, OpenSSH client, GitHub CLI, curl, jq, ripgrep, fd/find tooling, archive utilities, standard build toolchain and Git LFS.
- Include a tested stable Pi seed in the image so empty-home startup has a usable runtime without a successful fresh download.
- Record concrete base/package identities and tool versions in evidence.
- No secrets in source, layers, diagnostics or evidence.
- Do not add later extension/Web UI/MCP/subagent/browser scope.

### Must not / rationale that must travel

- Do not treat a mutable image tag or remembered package version as reproducibility evidence.
- Do not implement M02 latest-stable selection/fallback lifecycle here; T01 provides only the reproducible seed/base seam.

## Dependencies

- none

## Outcome

A repository-owned Docker base can be built on the permitted disposable Docker surface, contains the complete accepted tool inventory and a concrete stable Pi seed, and records the exact identities needed to reproduce/diagnose that build.

## Scope

### Included

- Dockerfile and minimal build metadata/scripts needed for the M01-W1 image.
- Current stable Pi seed version selection at execution time.
- Base-image/package/tool verification.
- Build evidence that captures concrete base/image/package identities without secrets.

### Excluded

- Compose mounts/service lifecycle and UID/GID/home initialization (T02).
- Git/GitHub operator setup, worktree fixture semantics and end-user TUI instructions (T03).
- Latest-stable-on-every-start, LKG promotion/fallback, graceful shutdown and image rollback (M02).
- Live OAuth credentials or live Unraid service replacement.

## Acceptance

- Image builds successfully on the permitted disposable Docker builder.
- `pi --version` works from the built image and matches the selected stable seed.
- All PIB-REQ-008 tools are present.
- Pi runs on a supported Node runtime.
- Evidence records resolved base-image identity plus selected Pi seed and representative tool versions.
- No secret material or unrelated host mounts are needed for the build/test.

## Required tests / checks

- Docker build from repository source.
- Version/presence checks for Node, Pi, Python, Git, SSH client, gh, curl, jq, rg, fd/find, archive tools, compiler/build tools and Git LFS.
- Inspect built image/user metadata sufficiently to ensure T01 has not accidentally introduced host secrets or unrelated mounts.
- Rebuild or equivalent source inspection proving adopted tooling is captured in image source.

## External write/readback needs

Build/test only with disposable Docker images/containers on the authorized `Tower` surface; do not modify the live Pi home/service. Read back image identity and command results.

## Independent review

`RECOMMENDED` — this establishes the supply-chain/runtime base used by every later milestone, so a fresh independent review is valuable before T02 builds persistence/privilege behavior on top of it.
