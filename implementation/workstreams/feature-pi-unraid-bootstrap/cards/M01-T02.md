- Milestone: `M01`

> Stable Task Card contract. Mutable state lives only in the selected workstream Task Board.

## Authority slice

- Master Plan / milestone contract: `planning/MASTER_PLAN.md#M01 — Reproducible non-root development environment`, especially M01-W2 and sections 2/3.1.
- Requirements: `PIB-REQ-001/002/003/006/007/011/013/017/018` plus applicable global invariants.
- Accepted decisions: `PIB-ADR-001`, `PIB-ADR-002`, relevant boundaries of `PIB-ADR-003`.
- Relevant OpenSpec: JIT candidate for initialization/permission behavior; create only if Refresh Gate confirms cross-file persistence/security ambiguity.
- Accepted dependency results: terminal GREEN result of `M01-T01`.

### Must preserve

- Exact host/container mount layout from ADR-002.
- Normal operation as configurable non-root UID/GID with sudo available inside the container.
- Initialization must be idempotent and must not recursively take ownership of existing projects/worktrees or overwrite a working home.
- No Docker socket, host-root, unrelated appdata or inbound SSH daemon.
- `unless-stopped`, `Europe/Zurich`, bounded Docker/backend logs.
- Existing CE workstation remains independent and untouched.

## Dependencies

- `M01-T01`

## Outcome

Compose and initialization source provide the accepted non-root persistent-home/mount foundation and fail safely on ownership/configuration problems using only disposable fixtures.

## Scope

### Included

- `compose.yaml` service/mount/restart/timezone/logging foundation.
- Configurable UID/GID and bounded privileged initialization if needed, followed by non-root normal operation.
- Idempotent persistent-home scaffolding and actionable permission diagnostics.
- Disposable mount fixtures and negative resolved-Compose inspection.

### Excluded

- Live OAuth/GitHub authentication.
- Runtime LKG updater/fallback, graceful Pi process shutdown and deployment rollback/update workflow.
- Any modification of existing real project/worktree ownership.

## Acceptance

- Resolved Compose uses only accepted mounts and no forbidden privileges/socket/root mount.
- Normal process identity is configured service UID/GID; sudo is available for legitimate container-local use.
- Repeated startup preserves fixture home content.
- Changed-UID/reused-home cases produce safe behavior or actionable failure, never silent recursive takeover.
- Restart/timezone/logging settings satisfy M01 contract.

## Required tests / checks

- `docker compose config` validation.
- Disposable fixture startup/restart tests with numeric uid/gid and ownership readback.
- Home before/after idempotency check.
- Negative mount/SSH-server/privilege inspection.
- JIT OpenSpec verification if one is created.

## External write/readback needs

Disposable directories/containers/images only on `Tower`; no live `/mnt/user/appdata/pi-unraid/home` mutation in M01.

## Independent review

`RECOMMENDED` — persistence, ownership and privilege boundaries are security/data-integrity sensitive.
