# M02-T03 — Host update operation and previous deployment rollback

- Milestone: `M02`

## Authority slice

- Master Plan / milestone contract: `planning/MASTER_PLAN.md#M02 — Recoverable runtime and deployment lifecycle`, especially M02-W3 and integrated checkpoint
- Requirements: PIB-REQ-014/015/017/020/021 plus global rollback/data-integrity invariants
- Accepted decisions: PIB-ADR-002/003
- Relevant OpenSpec: `openspec/changes/m02-runtime-lifecycle/`
- Research: `research/PI_UNRAID_M02_LIFECYCLE_FACTS_R1.md`
- Dependencies: terminal GREEN M02-T01/T02 results and M01 handoff

### Must preserve

- one normal user-facing update operation covers the expected repository/image/deployment path;
- repository synchronization is safe/fast-forward-only; local conflicts stop before deployment mutation;
- candidate image is built/verified separately before active-tag cutover;
- current known-working image and rendered deployment config are retained externally before cutover;
- rollback never rewrites/deletes home/projects/worktrees and requires no container Docker socket;
- rollback uses retained local artifacts and remains possible offline;
- deployment health/readback decides success; stale running status is insufficient;
- production/live cutover is not authorized in M02;
- retain at least active + one previous known-working deployment until a newer deployment is proven healthy.

## Dependencies

- M02-T02 terminal GREEN.

## Outcome

`scripts/update.sh` can safely stage the normal repository/image/deployment update, retain the current deployment, cut over only to a verified candidate, and automatically or explicitly restore the previous image/config after a broken disposable deployment without data loss.

## Scope

### Included

- host update transaction/locking and fast-forward-only repository sync;
- pre-update source/image/rendered-config snapshot;
- candidate image build/tag/verification;
- previous image tag plus external deployment-state metadata;
- health-gated cutover and previous deployment rollback;
- bounded cleanup/retention;
- operator recovery documentation;
- integrated M02 disposable failure-injection suite.

### Excluded

- executing the production script against the live Unraid `pi-unraid` service (M03 gate);
- Docker socket inside the container;
- restoring persistent home/repositories/worktrees from image rollback;
- live OAuth/GitHub acceptance.

## Acceptance

- disposable update records exact old source/image/config identities before mutation;
- successful candidate path records exact new source/image/runtime identities and becomes healthy;
- build/probe failure before cutover leaves current deployment unchanged;
- deliberately broken/unhealthy candidate after cutover restores the previous image/config and healthy state;
- rollback works with network disabled once artifacts are retained;
- fixture home/projects/worktrees content/ownership and runtime failed-candidate marker survive image rollback unchanged;
- one previous known-working deployment remains retained after success while only safely superseded artifacts are cleaned;
- update/runbook clearly separates automatic deployment rollback from explicit Git source recovery;
- integrated M02 checkpoint scenarios are durable evidence.

## Required tests / checks

- unique disposable Compose project, tags and external state directory;
- real Docker image IDs and rendered Compose snapshots;
- successful candidate build/readiness;
- deliberate broken candidate build/start/readiness paths;
- post-cutover rollback and offline rollback;
- before/after hashes/ownership for all three fixture bind sources;
- runtime selector and managed-shutdown regressions;
- log rotation/readiness readback.

## External write/readback needs

Real Docker/image/Compose writes are allowed only to uniquely named disposable M02 fixture resources and `/tmp` state. The production `scripts/update.sh` path is implemented/documented but **must not be run against the live Unraid service in M02**.

## Independent review

`REQUIRED` — host deployment replacement/rollback and persistent-data preservation are high-impact operational behavior.
