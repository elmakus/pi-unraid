# Canonical recovery bootstrap

Use this sequence only after explicit project selection.

1. Identify the selected repository and current branch/worktree from Git.
2. Read that repository's PROJECT.md for its workflow/workstream locator and project-level contract.
3. Read workflow/ROUTER.md from the current default branch of elmakus/project_workflow_v2.
4. Recover the exact selected workstream and only the durable pointers required by that router.
5. Progressively load only the exact current workflow module, authority, dependency results, review evidence, or technical contract selected by the router.
6. Re-read canonical Git state before a write when the branch, subject, or durable revision may have changed.

Do not reconstruct missing workflow policy from chat/session memory, Paseo metadata, model identity, or a parallel state store. The canonical router and repository state are the source for continuation semantics.
